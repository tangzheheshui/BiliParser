# 需求：试用 3 天 + 激活（授权模型改造）

> 状态：**已实现（2026-08-22）**。核心机制已归档进 [server.md](server.md) /
> [client.md](client.md)；本文档保留决策记录与后续待办。
> 用户原话：去掉鉴权、改成可试用 3 天、试用结束后必须激活；连服务器一起改、功能一起做（不只 UI）。

## 一、目标模型

```
首次启动 ──► 免激活，直接进工作台（试用 3 天）
               │ 状态卡显示「试用中（剩 X 天）」
               │ AI 走服务器代理，有每日限额
               ▼
          3 天到期 ──► 锁 AI 生成，弹激活窗
               │ 输码激活
               ▼
          一码一机（现有模型：永久/订阅、换机解绑）
```

## 二、核心决策（2026-08-22 已拍板，均取推荐项）

1. **试用状态存哪**：**服务器端记录**（设备指纹 → `trials.first_seen_at`）。
   删本地 `trial.json` / 改系统时间都无法重置（服务器按指纹返回同一 `first_seen_at`）。
2. **试用期 AI 谁出钱**：**服务器代理、卖家垫钱** + 试用期每日限额
   （默认 10 次/天，后台可按设备调）。
3. **「3 天」怎么算**：**72 小时精确起算**，用服务器时间（`TRIAL_HOURS=72`，可环境变量改）。
4. **到期锁什么**：**只锁 AI 生成**（字幕 / 解析还能看），总结按钮报「试用已到期」引导激活。

## 四、其他需求 / 坑（已识别）

- 试用期每日 AI 限额（默认多少？激活后配额更高）
- 防多设备刷试用：一个设备指纹只能试一次（服务器端去重）
- 本地 web 目前**没有设备指纹**，试用需要补一个稳定设备标识（新代码）
- ✅ **已确认：三种形态都要**（本地 web + 桌面 + 网页版）。试用机制以服务器端为准——
  本地版靠设备指纹、网页版按码/浏览器。
- **配置存储两套，保留差异**：本地版存本机 `config.toml`；网页版存服务端（按码加密）。
  两者别混（用户曾误会「配置保存在服务端」是 bug，实为网页版正常行为）。
- 试用 → 激活无缝衔接（配置 / 模板 / 缓存保留，不重置）
- 隐私说明：试用收集设备指纹，界面是否提示
- 管理后台状态扩展：现有「未激活 / 已使用·网页 / 已激活·桌面 / 已禁用」加「试用中」
