# 需求：试用 3 天 + 激活（授权模型改造）

> 状态：规划中（需求收集中，未实现）。本文档随需求逐步补充，实现后再归档进
> [server.md](server.md) / [client.md](client.md)。
> 用户原话：去掉鉴权、改成可试用 3 天、试用结束后必须激活；连服务器一起改、功能一起做（不只 UI）。

## 一、目标模型

```
首次启动 ──► 免激活，直接进工作台（试用 3 天）
               │ 状态卡显示「试用中（剩 X 天）」
               │ AI 走服务器代理，有每日限额
               ▼
          3 天到期 ──► 锁 AI 生成，弹激活窗
               │ 输码激活
               ▼
          一码一机（现有模型：永久/订阅、换机解绑）
```

## 二、核心决策（待用户拍板，标了推荐）

1. **试用状态存哪**（决定防绕过强度）
   - A 本机存 `trial.json`：简单，但删文件 / 改系统时间就能重置 → 等于没防
   - B **服务器端记录**（设备指纹 → 首次连接日期）← 推荐

2. **试用期 AI 谁出钱**
   - A **服务器代理、卖家垫钱** + 试用期每日限额（如 10 次/天）← 推荐
   - B 用户自带 key：卖家零成本，但门槛高

3. **「3 天」怎么算 + 时间来源**
   - 自然日 vs **72 小时精确起算** ← 推荐
   - 时间用**服务器时间**（防改本地时钟）

4. **到期锁什么**
   - 只锁 AI 生成（字幕 / 解析还能看）← 推荐；还是整个 app 锁死

## 三、改动范围

| 块 | 改什么 |
|---|---|
| 客户端（本地 web + 桌面，共用前端） | 去掉启动即激活；试用倒计时；到期弹激活窗 |
| 授权服务器 `license-server/` | 试用接口（登记指纹 / 查状态 / 扣配额）；试用期 AI 代理 |
| 管理后台 | 「试用中」状态、试用设备列表、试用配额调整 |
| 网页版 `hosted.py`（✅ 要一起做） | 试用语义：按码还是按浏览器（待定） |

## 四、其他需求 / 坑（已识别）

- 试用期每日 AI 限额（默认多少？激活后配额更高）
- 防多设备刷试用：一个设备指纹只能试一次（服务器端去重）
- 本地 web 目前**没有设备指纹**，试用需要补一个稳定设备标识（新代码）
- ✅ **已确认：三种形态都要**（本地 web + 桌面 + 网页版）。试用机制以服务器端为准——
  本地版靠设备指纹、网页版按码/浏览器。
- **配置存储两套，保留差异**：本地版存本机 `config.toml`；网页版存服务端（按码加密）。
  两者别混（用户曾误会「配置保存在服务端」是 bug，实为网页版正常行为）。
- 试用 → 激活无缝衔接（配置 / 模板 / 缓存保留，不重置）
- 隐私说明：试用收集设备指纹，界面是否提示
- 管理后台状态扩展：现有「未激活 / 已使用·网页 / 已激活·桌面 / 已禁用」加「试用中」

## 五、客户端 UI 待办（用户反馈）

- **设置界面整理**：布局有点乱，待细化
- **API Key 输入框置灰**：「AI 提供商」默认选「服务器模型」时，key 输入框应置灰（禁用），
  切到智谱 / DeepSeek 才可填
  - （备注：现有 `syncProviderUI()` 已有置灰逻辑，但界面仍显乱 / 疑似未生效，实现时核对）
- **页面整洁（去「脏兮兮」）**：长段文字说明不要平铺在页面上，改成按钮 hover 时显示（tooltip）
  - 典型：设置面板的 SESSDATA 6 步获取教程（当前平铺很长）、模板编辑器里的长 placeholder、
    生成按钮下方的小字说明等——这类说明收到 hover 提示里，界面只留精简标签
