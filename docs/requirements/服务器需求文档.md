## 1. 项目背景与授权模式

配套的桌面客户端为已有程序（仅做鉴权逻辑改造），无用户账号体系，授权完全依赖激活码。**授权模式为一次性激活：**

1. **备货**：服务器自动维持一个激活码库存池（默认一批，用完自动补），卖家无需手动"生成"；
2. **发货**：买家下单后，卖家在管理页点一下"取码"，从未发货库存中取出一个激活码，**复制文本、手动发给买家**（微信/QQ 皆可）；
3. **激活**：买家将码填入客户端，客户端调用服务器激活接口（携带本机 MAC）；
4. **绑定**：服务器将激活码与该 MAC 绑定，下发**签名凭证**；客户端本地保存，此后**永久使用、不再联网校验**；
5. **恢复**：用户重装系统导致本地凭证丢失时，用原码原机重新激活，服务器必须放行并重新下发凭证。

> ⚠️ 与"每次启动在线校验"模式的本质区别：服务器只在**激活瞬间**被需要一次，之后服务器宕机不影响任何已激活用户。相应地，服务器**不具备远程吊销能力**（已激活客户端不再询问服务器），这是有意接受的取舍。

## 2. 术语定义

| 术语 | 说明 |
|---|---|
| 激活码（SN） | 服务器生成的授权凭据，**永久有效**，一码绑定一台设备 |
| MAC 地址 | 客户端设备物理网卡地址，作为设备唯一标识 |
| 库存池 | 服务器中"未发货"状态激活码的集合，自动补货维持 |
| 发货 | 卖家在管理页取码并复制给买家的动作，纯文本传递 |
| 凭证（token） | 服务器对 `sn + mac + activated_at` 的 HMAC-SHA256 签名，客户端持久化保存用于本地自证 |

### 2.1 激活码三态

```
[未发货] --卖家取码--> [已发货] --买家激活--> [已激活]
    ▲                      │
    └────── 卖家退回 ──────┘
（已激活为终态，不可退回、不可重置）
```

| 状态 | 含义 | 库存池 |
|---|---|---|
| `unshipped` 未发货 | 已生成，躺在库存池里 | ✅ 计入 |
| `shipped` 已发货 | 已被卖家取走发给买家，尚未激活 | ❌ |
| `activated` 已激活 | 已绑定 MAC，完成使命 | ❌ |

## 3. 系统架构与边界

```
[买家] --运行--> [客户端安装程序]（已有程序，仅改鉴权逻辑）
                    │ ①启动：本地校验凭证，通过则直接使用（不联网）
                    │ ②无凭证时：POST 激活接口（mac + sn）
                    ▼
              [授权服务器]（公网云服务器）
                    ▲
[卖家/管理员] --登录--> [管理后台页面]
                         ├─ 取码发货（一键取一个未发货码 → 复制文本）
                         └─ 激活码列表（三态筛选 / 退回）
```

**不在本期范围：** 用户注册体系、支付、远程吊销/黑名单、版本更新分发、客户端防逆向加固、二维码/图片发货、**通知下发**（已明确移除）。

## 4. 功能需求

优先级：P0 = 本期必须实现；P1 = 预留设计，本期不做但结构留余地。

### 4.1 激活鉴权（P0，核心）

**FR-01** 提供 HTTP 激活接口，接收客户端上送的 `mac` 与 `sn`，按下表**自上而下**判定，命中即返回：

| # | 条件 | 处理 | 返回码 |
|---|---|---|---|
| 1 | `sn` 缺失或为空 | 直接返回，不查库 | `1` 未激活 |
| 2 | `mac` 缺失或为空 | 直接返回 | `4` 参数错误 |
| 3 | `sn` 在库中不存在 | 直接返回 | `2` 无效激活码 |
| 4 | `sn` 存在且未绑定 MAC（无论未发货/已发货） | 绑定本次 MAC，状态置为**已激活**，记录激活时间，生成签名凭证下发 | `0` 激活成功 |
| 5 | `sn` 已激活且绑定 MAC 与本次一致 | **放行**，重新生成凭证下发（覆盖重装系统恢复场景） | `0` 激活成功 |
| 6 | `sn` 已激活但绑定 MAC 与本次不一致 | 直接返回 | `3` 设备不匹配 |

> 规则 4 刻意**不要求"已发货"作为激活前置条件**：发货状态只是卖家的管理记录，若卖家跳过取码、直接从列表复制了未发货的码发给买家，激活同样放行（状态直接跳变为已激活），避免"忘了点取码导致买家激活失败"的售后事故。

**FR-02** MAC 规范化：忽略大小写与分隔符（`:`、`-`），如 `AA:BB:CC:DD:EE:FF` ≡ `aabbccddeeff`。存储统一为去分隔符大写。

**FR-03** 激活码规范化：忽略大小写与首尾空格，库内统一大写存储。

**FR-04** 激活成功时计算并下发签名凭证：`token = HMAC-SHA256(secret, sn + "|" + mac_normalized + "|" + activated_at)`；`secret` 来自环境变量 `LICENSE_SIGN_KEY`（32 位以上随机字符串），**不得硬编码**。客户端将内置同一密钥做本地验签。

**FR-05** 激活接口为匿名公开接口，无需任何登录凭证。

**FR-06** 每次激活请求写入日志（见 7.2），无论成败。

### 4.2 激活码库存池与自动补货（P0，核心）

**FR-10** 服务器自动维持"未发货"激活码库存，**卖家全程无"生成"操作**：

| 触发时机 | 行为 |
|---|---|
| 服务启动时库存为 0 | 自动生成一批（默认 50 个） |
| 每次取码后，未发货库存 < 阈值（默认 10） | 自动补货至目标值（默认 50 个） |

补货参数走环境变量（`RESTOCK_THRESHOLD`、`RESTOCK_TARGET`），不配置则用默认值。

**FR-11** 激活码**永久有效**，无过期时间（表结构预留 `expires_at` 字段，NULL = 永久）。

**FR-12** 补货生成时支持统一备注（如按批次"2026-08 批次"），便于按批次追踪。

**FR-13** 激活码格式：
- `XXXX-XXXX-XXXX-XXXX`（16 位有效字符，4 段）；
- 字符集：`23456789ABCDEFGHJKMNPQRSTUVWXYZ`（剔除 `0/O/1/I/L` 易混淆字符）；
- 使用密码学安全随机源（Python `secrets` 模块），入库前查重保证全局唯一。

### 4.3 取码发货（P0，核心交互）

**FR-20** 管理页提供醒目的**"取一个激活码"**按钮，点击后：
1. 从未发货库存中取出一个（FIFO，取最旧的）；
2. 该码状态置为**已发货**，记录发货时间；
3. 页面大字展示该码，并附**一键复制**按钮（复制纯文本激活码，如 `ABCD-1234-EFGH-5678`）；
4. 卖家手动粘贴发给买家（微信/QQ/短信均可，服务器不参与发送）。

**FR-21** 取码接口同步提供（HTTP API），与页面按钮等价，便于将来接自动发货脚本。

**FR-22** 已发货且未激活的码支持**退回**：状态还原为未发货、清空发货时间，可再次被取出发货（误发场景）。

**FR-23** **已激活的码不可退回、不可重置**（终态）。

### 4.4 管理后台页面（P0）

**FR-40** 极简单页 Web 管理页（原生 HTML + JS 即可，无需前端框架），功能：
1. 管理员登录（密码校验）；
2. **取码发货**（见 4.3，首屏主按钮）；
3. 激活码列表：激活码、状态（未发货/已发货/已激活三态筛选）、绑定 MAC、创建时间、发货时间、激活时间、备注；支持分页；
4. 已发货未激活的码可一键退回；
5. 库存余量提示（当前未发货数量一目了然）。

**FR-41** 管理密码走环境变量/配置文件（未配置则管理功能不可用并明确报错），**不得硬编码**。

**FR-42** 登录成功签发 Token（有效期 ≥ 7 天，便于个人日常使用；浏览器记住密码兜底），管理类 API 与页面操作均需携带。Token 对管理员透明，无需自己记忆。

### 4.5 预留功能（P1，本期不做）

- **二维码发货**：单码导出二维码 PNG、批量导出 ZIP——将来上自动发货或实体卡时启用；
- **解绑/换机**：管理员手动清空某已激活码的 MAC 绑定（表结构已支持）；
- **手动补货/手动生成**：绕过自动补货强制生成一批；
- 激活码有效期（按天定期授权）；
- 批量导入/导出 CSV。

## 5. 接口设计

统一约定：
- Base URL：`/api/v1`；请求/响应均为 JSON；
- **所有业务响应 HTTP 状态码统一 200**，业务结果放响应体 `code` 字段（客户端只解析一处）；
- 服务器内部异常统一返回 `code=500`。

### 5.1 激活接口（客户端调用，匿名）

```
POST /api/v1/license/activate
请求：{ "mac": "AA:BB:CC:DD:EE:FF", "sn": "ABCD-1234-EFGH-5678" }

成功响应：
{
  "code": 0,
  "message": "激活成功",
  "data": {
    "sn": "ABCD-1234-EFGH-5678",
    "mac": "AABBCCDDEEFF",
    "activated_at": "2026-08-25 18:00:00",
    "token": "hmac签名值"
  }
}
```

> `data` 在非成功状态下可为空对象。

### 5.2 管理员登录

```
POST /api/v1/admin/login
请求：{ "password": "..." }
响应：{ "code": 0, "data": { "token": "..." } }
密码错误返回 code=401。
```

### 5.3 取码发货（需 Token，核心）

```
POST /api/v1/admin/codes/take
请求：{}（无参数）
响应：
{
  "code": 0,
  "message": "ok",
  "data": { "sn": "ABCD-1234-EFGH-5678", "shipped_at": "2026-08-25 18:30:00" }
}
```

> 服务端保证原子性：并发多次取码不会取到同一个码；库存为空时自动补货后再取（正常不会出现取不到的情况，若极端情况仍为空返回 `code=501` 附明确提示）。

### 5.4 退回（需 Token）

```
POST /api/v1/admin/codes/{sn}/return
响应：{ "code": 0, "message": "已退回未发货" }
仅限已发货且未激活的码；其他状态返回 code=4。
```

### 5.5 激活码列表（需 Token）

```
GET /api/v1/admin/codes?page=1&page_size=20&status=unshipped|shipped|activated|all
响应：
{
  "code": 0,
  "data": {
    "total": 100,
    "unshipped_count": 43,
    "items": [
      { "sn": "...", "status": "shipped", "bound_mac": null,
        "created_at": "...", "shipped_at": "...", "activated_at": null, "remark": "..." }
    ]
  }
}
```

> `unshipped_count` 为当前库存余量，管理页首屏展示。

## 6. 返回码定义

| code | 含义 | 触发条件 |
|---|---|---|
| `0` | 成功 | 各接口正常完成 |
| `1` | 未激活 | 激活请求 `sn` 为空或缺失 |
| `2` | 无效激活码 | 码在库中不存在 |
| `3` | 设备不匹配 | 码已激活但绑定其他 MAC |
| `4` | 参数错误 | `mac` 为空；或退回操作对象状态不符合要求 |
| `401` | 未授权 | 管理 API 缺少/错误 Token，或登录密码错误 |
| `429` | 请求过于频繁 | 触发限流 |
| `500` | 服务器内部错误 | 服务端异常 |
| `501` | 库存异常 | 取码时库存为空且补货失败（极端兜底） |

## 7. 数据模型（SQLite）

### 7.1 激活码表 `license_codes`

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `id` | INTEGER | PK, 自增 | |
| `sn` | TEXT | UNIQUE, NOT NULL | 激活码，统一大写 |
| `status` | TEXT | NOT NULL, 默认 `unshipped` | `unshipped` / `shipped` / `activated` |
| `shipped_at` | TEXT | NULL | 发货（被取走）时间；退回时清空 |
| `bound_mac` | TEXT | NULL | 规范化后 MAC；NULL = 未激活 |
| `remark` | TEXT | 默认空 | 备注（批次等） |
| `expires_at` | TEXT | NULL | 预留，NULL = 永久（本期恒为 NULL） |
| `created_at` | TEXT | NOT NULL | 生成时间 |
| `activated_at` | TEXT | NULL | 激活时间 |

> 状态与绑定字段存在冗余（`status=activated` ⇔ `bound_mac` 非空），以 `bound_mac` 为准做激活判定，`status` 服务于管理与筛选；两者在同一事务内更新，保证一致。

### 7.2 激活日志表 `activate_logs`

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | INTEGER PK | |
| `sn` | TEXT | 上送的序列号（可为空） |
| `mac` | TEXT | 上送的 MAC |
| `result_code` | INTEGER | 本次返回业务码 |
| `ip` | TEXT | 来源 IP |
| `created_at` | TEXT | 请求时间 |

> 日志用途：售后排查（如"码被别人绑了"可查绑定者 IP 与时间）、粗略统计激活量。

## 8. 非功能需求

| 编号 | 需求 | 优先级 |
|---|---|---|
| NFR-01 | 单机部署，预期并发极低（激活是一次性事件） | 必须 |
| NFR-02 | 激活、取码接口响应 < 200ms（不含网络） | 必须 |
| NFR-03 | 激活接口限流：每 IP 每分钟 ≤ 60 次，超限返回 `code=429`（防激活码暴力枚举） | 应该 |
| NFR-04 | 生产部署使用 HTTPS（建议 nginx 反代 + Let's Encrypt；初期 IP + HTTP 可先行） | 应该 |
| NFR-05 | 配置项全部走环境变量/配置文件：`ADMIN_PASSWORD`、`LICENSE_SIGN_KEY`、`RESTOCK_THRESHOLD`、`RESTOCK_TARGET`、数据库路径 | 必须 |
| NFR-06 | SQLite 数据文件定期备份（cron 拷贝即可），重启不丢库存与绑定关系 | 必须 |
| NFR-07 | 取码操作原子性（SQLite 事务即可满足），并发下不重复发码 | 必须 |

## 9. 技术栈与部署建议

**推荐方案：Python 3.10+ / FastAPI / SQLite / Uvicorn**

| 组件 | 选型 | 理由 |
|---|---|---|
| Web 框架 | FastAPI + Uvicorn | 自动生成 `/docs` 在线接口文档，客户端联调零成本 |
| 数据库 | SQLite（标准库 `sqlite3`） | 零运维、单文件、备份即拷贝、天然支持事务（取码原子性） |
| 管理页 | 单个静态 HTML + 原生 JS | 无需前端构建工具链 |
| 部署 | 国内云厂商**轻量应用服务器**最低配（1核1G 足够）+ systemd 守护 + nginx | 一年成本几十元 |

> 备选：Node.js + Express + better-sqlite3（开发者更熟 JS 时，功能完全等价）。
> 域名与备案非必需：初期客户端可直连 `http://IP:端口`，正式上线建议域名 + HTTPS。
> 注：二维码依赖（qrcode/pillow）本期不需要，P1 启用时再加。

## 10. 验收标准

| # | 场景 | 预期 |
|---|---|---|
| 1 | 空库首次启动服务 | 自动生成一批（默认 50 个）未发货码 |
| 2 | 调取码接口 | 返回一个码（最旧的），状态变**已发货**，记录发货时间 |
| 3 | 连续取码至库存 < 10 | 自动补货至 50 |
| 4 | 取码后库存余量 | 列表接口的 `unshipped_count` 正确递减 |
| 5 | 已发货的码 + MAC-A 激活 | `code=0`，状态变**已激活**，返回 token，绑定 MAC-A |
| 6 | **未发货的码直接激活（跳过取货）** | **同样 `code=0`，状态直接变已激活**（宽容设计） |
| 7 | 已激活 + 同 MAC 再次激活（模拟重装系统） | `code=0`，重新下发 token |
| 8 | 已激活 + MAC-B 激活 | `code=3`，绑定关系不变 |
| 9 | MAC `aa:bb:cc:dd:ee:ff` 与已绑定 `AA:BB:CC:DD:EE:FF` | 视为同一设备，`code=0` |
| 10 | 退回已发货未激活的码 | 状态还原未发货，可再次被取出 |
| 11 | 退回已激活的码 | 拒绝（`code=4`） |
| 12 | `sn` 为空 / `mac` 为空 / 不存在的码 | 分别返回 `1` / `4` / `2` |
| 13 | token 可被客户端用相同密钥复算验证 | 一致 |
| 14 | 批量生成格式 | 全部唯一，符合 FR-13 |
| 15 | 未登录调 `/api/v1/admin/codes/take` | `code=401` |
| 16 | 服务器重启后重复用例 2、7 | 结果一致（持久化生效） |
